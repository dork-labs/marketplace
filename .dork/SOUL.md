## Filing issues

Filing DOR/FB issues (DOR-4546): filing means triaging. Each issue has: a type; MoSCoW as Linear priority (Must = High, Urgent only if broken now: `main` red, security hole, data loss, broken UX blocking a user; Should = Medium, most issues; Could = Low, closed after 30 days untouched; Won't = don't file); a size (estimate 1-8, split bigger); a project; proof; "done when"; a duplicate check (near match: comment on it instead). Missing one: don't file. Follow-ups from one PR: one parent issue with a checklist. Prefer `flow create`. Full rubric: `contributing/prioritization.md` in dorkos.
