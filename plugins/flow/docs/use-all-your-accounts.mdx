# Use all your accounts

With several Claude Code, Codex or OpenCode accounts on this computer, flow can spread its work across them. When one reaches its limit, work moves to another instead of stopping.

**The full guide lives on the DorkOS site: [Use all your accounts](https://dorkos.ai/docs/guides/flow/use-all-your-accounts).** It covers the three roles (main, rotation, kept out), setup in the terminal and in the DorkOS app, and what to do when something looks wrong.

This is built for one person using their own accounts. Whether that fits Anthropic's terms, or any other service's, is your call to judge. Don't use it to share accounts between people. Keep a work or client account out unless you are allowed to use it this way.

The short version:

```bash
flow accounts setup          # asks, then shows every change before making it
flow accounts setup --help   # every flag, for scripts and agents
flow accounts                # each account's role and room left
```

## Which projects an account may work in

DorkOS decides which accounts each project may use, and holds every chat, schedule and handoff there to it. Each project's Flow settings show **Accounts this project may use**. You change it in Settings → Runtimes, where you can limit an account to projects. `flow next` and `flow drain` follow the same rule.

This replaces flow's older **Only for these repos** list on a kept-out account. In Settings → Flow, that account's row says what to do, and nothing moves until you press a button:

1. **Limit this account in Settings → Runtimes**: there, limit it to the projects the row names. Flow never suggests a wider limit, and leaves alone an account DorkOS already limits.
2. **Switch to DorkOS's rule** then lets flow use the account in rotation within those limits, and drops flow's own list. While a project runs flow older than 0.52, the row says **Note it** instead, both rules apply, and the switch appears once every project is updated.

To undo it, clear the account's project limits in Settings → Runtimes, and put flow's list back with `flow accounts set <id> --role kept-out --repos owner/name,...`.

To see each account's limits, see [Account usage](./account-usage.mdx).
