# Account usage and the fleet view

If you run several Claude Code accounts, each one has a 5-hour limit and a weekly limit. flow can keep a record of how much of each you have used and when each limit resets. `flow fleet` then shows all of it on one screen, next to every session that is running and the item it is working on.

This is account-aware scheduling for one person's own accounts. Whether using several of your own accounts this way fits Anthropic's terms is your call to make.

## What flow records, and from where

flow tracks the accounts listed in `~/.dork/config.json`, the same list the DorkOS app keeps: Claude Code's under `runtimes.claudeCode.accounts`, and Codex's and OpenCode's under `runtimes.codex` and `runtimes.opencode`. A runtime with no list has one account, `default`: whatever it is signed in to.

For each account flow keeps one small file at `~/.dork/runtimes/<runtime>/usage/<account>.json`, holding the latest reading of each limit: how much is used, when it resets, and when that was seen. For a pay-as-you-go account it also holds what you spent.

For Claude Code, flow reads these numbers only from what Claude Code itself shows:

- **The status line.** While you use an account in the terminal, Claude Code hands its status-line script the 5-hour and weekly numbers. Two added lines pass them to flow in the background.
- **Past conversations.** When an account runs out, Claude Code saves a message saying so, with the reset time. `flow usage scan` reads those.
- **A short check-in turn.** `flow usage probe` sends one short message on an account and reads the numbers Claude Code reports back.

flow never reads your sign-in, never looks in the macOS Keychain, and never asks Anthropic's servers for usage directly.

After a limit's reset time, flow counts it as empty.

## Keep the numbers current: the status line

Run this to see what flow would change:

```bash
node --experimental-strip-types <flow-root>/scripts/flow.ts usage install-statusline
```

For each account it finds the status-line script in that account's `settings.json` and plans two lines, placed right after the line that reads the status-line input (such as `input=$(cat)`):

```bash
# flow usage recorder (opt-in): records this account's usage for `flow fleet`. See <flow-root>/docs/account-usage.mdx
{ [ -x '<flow-root>/scripts/usage/statusline-hook.sh' ] && printf '%s' "$input" | FLOW_NODE='<node>' '<flow-root>/scripts/usage/statusline-hook.sh'; } >/dev/null 2>&1 &
```

Nothing changes until you add `--yes`. Then flow:

- keeps a copy of each script next to it (`<script>.flow-backup-<time>`),
- changes nothing else in the file, and
- checks the result, and puts the copy back if the check fails.

`--remove --yes` takes the two lines out again. `--account <id>` limits it to one account.

The recorder runs in the background and starts Node only when a number changed.

When flow cannot edit a status line (an inline command, or a script that never saves its input), it prints the two lines to add by hand. If you move the flow plugin, run `install-statusline --yes` again.

## Catch up: scan past conversations

```bash
node --experimental-strip-types <flow-root>/scripts/flow.ts usage scan
```

This reads the last 8 days of saved conversations for every registered account and records each time an account ran out. `--days <n>` changes the window, `--all` reads everything, and `--dry-run` shows what it would record. Running it twice changes nothing.

## An account nobody has used lately: probe it

```bash
node --experimental-strip-types <flow-root>/scripts/flow.ts usage probe <account>
```

Without `--yes` this only tells you what it would do. With `--yes` it sends one short message on that account (model `haiku`, no tools, no files) and records the numbers Claude Code reports. It uses a small part of that account's 5-hour limit. If no 5-hour window is running, it starts one.

If the account turns out to use an API key, flow records nothing and says so.

## Clean up

`flow usage prune` deletes the files of accounts you removed from the list. `--dry-run` shows them first. It never deletes a runtime's `default`.

## Read the fleet screen

```bash
node --experimental-strip-types <flow-root>/scripts/flow.ts fleet
```

```
Accounts             5-hour                       week
  claude2  main      [####......]   41%  2h 14m   [#######...]   72%  3d 04h
                     reserve 50%, seen 3m ago

Sessions
  claude2  DOR-2370  busy  cli  1a2b3c4d  ~/project-wt/feature  3h

Sessions on accounts flow does not know are not shown.
DorkOS: not running at http://127.0.0.1:4242
```

**Accounts**, one per line:

- Its role: `main`, `rotation` or `kept-out`, from `~/.dork/flow/fleet.json`, keyed `<runtime>:<account>`. A listed account with no entry is `kept-out`; a `default` is `rotation`.
- A bar and a percentage for the 5-hour and the weekly limit, and how long until each resets.
- `out` means the account hit that limit. `reset` means it has reset since the last reading. `no reading` means flow never saw that limit, or the last reading is too old to trust.
- Notes: the reserve you keep for yourself, when the account ran out, and how long ago flow last saw its numbers.

**Sessions**, one per line: the account, the item it works on (if flow started it), what it is doing, where it runs, the start of its session id, its folder, and how long it has been running.

| State     | Meaning                                                        |
| --------- | -------------------------------------------------------------- |
| `busy`    | Working right now.                                             |
| `idle`    | Waiting for its next message.                                  |
| `parked`  | Waiting on you: a question, an approval, or a review.          |
| `limited` | Its account ran out; it can continue after the reset.          |
| `stale`   | flow has a run for it, but its worker process is gone.         |
| `unseen`  | flow has a run for it, but no session list shows it right now. |

Where it runs is `cli` (a terminal), `dorkos` (the DorkOS app) or `cmux`. flow asks a DorkOS app on this computer for its sessions; `--no-dorkos` skips that.

`flow fleet` only reads; it changes nothing. Add `--json` for the same data as one JSON object.
