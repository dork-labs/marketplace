# When project hooks are off

You can still run Flow one stage at a time when DorkOS leaves its project hooks off.
Hooks are small commands that Claude Code runs between tools or when a session tries to stop.

Below Full, DorkOS asks you before it turns Flow's two project hooks on.
From DorkOS 0.133.0, its card shows each hook command in full, with a button to allow them and **Decline**.

A card can still offer only **Decline**, with: "This request can't be shown in full, so it can't be allowed yet."
That message does not mean Flow is broken.
On 0.133.0 or later, declining that card is not saved as a lasting refusal.
On an older DorkOS, leave that card alone, including Decline: there a refusal lasts.

## What changes

- **Terminal queue:** `/flow auto` can stop before the queue is finished.
  The Stop hook normally keeps its owning session working while ready work remains.
- **Usage warnings:** Claude Code loses Flow's between-tool usage warnings.
  The PostToolUse hook normally checks usage after each tool call.
- **Other work:** manual stages and the scheduled tick still work.
  The scheduled tick needs its usual DorkOS setup and an enabled schedule.

Flow's `status`, `/flow:self-test`, and panel do not report whether DorkOS withheld these hooks.
A passing self-test does not prove they are enabled.

## After Decline

DorkOS remembers your refusal for that project's hook commands.
It will not ask again on its own, even if the scripts they run change.
Changing the commands makes a different request.

From 0.133.0, the Inbox lists packages whose hooks you declined, with **Ask again**.
Your refusal stays in place until you answer the new card.

You can also clear Flow's saved decision:

```bash
dorkos harness hooks --revoke flow
```

This clears Flow's saved hook approvals and refusals across projects on this computer.
It grants nothing.
DorkOS can ask again when you install Flow or click **Sync now**.
Running `dorkos harness sync --fix` alone holds undecided hooks back without asking.

Use `dorkos harness hooks --list` to see saved decisions.
That list records decisions, not proof that a running session loaded the hooks.

## Reference

For contributors checking the commands: `hooks/hooks.json` declares Stop as `flow-loop.mjs`.
It declares PostToolUse as `flow.ts limit-check --hook`.
