# Draining in parallel

`flow drain --parallel 3` carries three ready items at once, each in its own worktree and on its own account. A separate reviewer reads every push; a PR opens only after a clean review of the head.

## Before you start

Allow each account flow may spend with `flow accounts set <id> --role rotation`. Each user judges their own use of more than one account against Anthropic's terms.

## Where sessions run

`--host` picks `cli`, `cmux` or `dorkos`; `auto` tries cmux, DorkOS, then CLI.

## What each line means

- `claimed on <account> (cli)`: a worker started.
- `reviewer started at 4be1c2d`: a push is under review.
- `sent review-findings`: the worker got the findings.
- `sent open-pr`: the review came back clean.
- `moved to <account>`: its account ran out.
- `restarted on <account>`: its session went away.
- `parked: <reason>`: a person is needed.
- `removed`/`kept its worktree`: the item finished. Ignored files go too; an idle DorkOS worker counts as stopped.

## What happens at a limit

Near a limit, the worker finishes its step, checkpoints and stops. If the account resets within `drain.waitIfResetWithinMinutes`, the run waits. If only one model ran out, it goes on with the next in `drain.modelFallback`. Otherwise another account's session continues from `HANDOFF.md`.

## Ask or auto

`handoff` in `fleet.json` decides: `auto` moves the run at once; `ask` comments the `flow handoff <id> --to <account>` command and waits for the reset. `flow handoff <id> --wait` keeps a run where it is.

## When a session goes quiet

After `drain.stallAfterMinutes` (default 60) without progress, a session that went away restarts once from `HANDOFF.md` on an account with room; otherwise the run parks. One waiting on you is only listed, by `flow status`.

## Caps

New sessions wait while load per CPU reaches `drain.maxLoadPerCpu` or an account has `drain.maxLivePerAccount` sessions. Fewer-session accounts go first; a stale usage reading gets none until the hourly probe refreshes it. After `drain.maxReviewRounds` rounds the run parks.

## Terminal or schedule

`flow drain` repeats every `drain.pollSeconds` until done or Ctrl-C. A schedule runs `flow drain --tick`. With no pass for twice `drain.stallAfterMinutes`, `flow status` says so.

## Permissions

Workers start in `drain.permissionMode`, default `acceptEdits`, which runs only what your repo's settings allow. `bypassPermissions` also needs a person to approve Flow's **Allow unattended bypass** card in DorkOS, for 30 days or until your flow settings change, and flow must be installed globally, not per agent; otherwise `acceptEdits`. It won't start on uncommitted settings or adapter code. Guard hooks still run.

## Parts

Sessions read `templates/drain/worker-brief.md` and `templates/drain/reviewer-brief.md`. `flow watch` waits on a PR by hand.
