# Draining in parallel

flow's own loop carries one item at a time. To carry several ready items at once today, one session acts as the orchestrator and runs this recipe by hand. It uses three files that ship with flow:

- `templates/drain/worker-brief.md`: one worker's path from claim to DONE.
- `templates/drain/reviewer-brief.md`: an independent reviewer's rubric for one pushed commit.
- `templates/drain/watch.sh`: watches open PRs and exits when one merges, fails a check, or leaves the merge queue.

## The recipe

1. **Pick the items.** Run `/flow:status` and take the ready items you want. Items that touch the same files go to the same worker, or wait for each other.
2. **Fill the placeholders.** Copy the two briefs and replace each `<placeholder>` (`<project>`, `<flow-root>`, `<workspaces-dir>`, `<scratch-dir>`). `<flow-root>` is where flow is installed: take the real path of `.claude/skills/flow__closing-work` (`realpath`) and go two directories up. Add your repo's own landing rules if its `AGENTS.md` does not already cover them.
3. **Start one worker per item.** Give each a background agent the worker brief and its item ids. Each claims, builds in its own worktree, pushes, and returns.
4. **Review each pushed commit.** Start a fresh agent per worker with the reviewer brief and the pushed SHA. Send its findings back to that worker. Repeat until the verdict is clean.
5. **Land.** Tell the worker to open its PR. Run `watch.sh <owner/repo>:<pr> ...` over the open PRs, and resume the worker when its PR merges or goes red.
6. **Close.** Each worker runs DONE for its items and removes its worktree.

## Rules that keep it safe

- One writer per worktree. The reviewer reads the pushed commit in its own worktree, never the worker's.
- Workers must be resumable: the orchestrator messages the same agent after review and after merge.
- Cap how many workers run at once. A loaded machine times out tests, and reruns cost more than waiting.
