# Draining in parallel

`flow drain --parallel 3` carries several ready items at once, three sessions at a time. For each item it makes a worktree, claims the item, and starts a worker on the account with the most room. Every push the worker reports is read by a separate reviewer session in its own worktree. The worker opens its PR only after a clean review at the branch head: `flow pr` refuses otherwise.

## Before you start

Allow each account flow may spend with `flow accounts set <id> --role rotation`. With none registered, sessions run on your own login. Each user judges their own use of more than one account against Anthropic's terms.

## Where sessions run

`--host` picks `cli` (plain `claude -p`), `cmux` (a workspace per session) or `dorkos`. `auto` takes cmux when the drain runs inside it, then DorkOS when it is running, then the plain CLI. A named host that is missing is an error.

## What each line means

- `claimed on <account> (cli)`: a worker started.
- `reviewer started at 4be1c2d`: a push is under review.
- `sent review-findings`: the worker got the findings.
- `sent open-pr`: the review came back clean.
- `parked: <reason>`: a person is needed; the reason is posted on the item.

## Limits

No new session starts while the load per CPU is at or above `drain.maxLoadPerCpu`, or on an account already carrying `drain.maxLivePerAccount` sessions. After `drain.maxReviewRounds` reviews asking for changes, the run parks.

## Terminal or schedule

In a terminal, `flow drain` passes every `drain.pollSeconds` until nothing is left, or until Ctrl-C, which leaves every session running for the next drain to adopt. On a schedule, set `drain.parallel` and the `flow-drain` tick runs `flow drain --tick`, one pass per firing.

## Parts

- `templates/drain/worker-brief.md` and `templates/drain/reviewer-brief.md`: what each session reads first.
- `flow watch`: wait on any PR by hand.
- The launchers' live test starts real sessions only with `FLOW_LAUNCHER_LIVE=1`.
